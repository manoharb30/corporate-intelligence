## Architectural finding #2 — SnapshotBlob ↔ SP divergence (surfaced post-pause)

User noticed the **dashboard "Last 90d" shows only 10 signals** (GO, NSP, PICS, FMNB, GPGI, BETR, RPC, GRNT, AVBC, ALT) while **SignalPerformance has ~22 immature strong_buy rows** in the same window. Investigated and reached precise diagnosis:

- `SnapshotBlob {days:30/60/90}` is a precomputed cache (correct design) — dashboard hits `SnapshotService._load_precomputed` first, no recomputation per page-load. User correctly pushed back on Claude's initial "recomputes on every refresh" framing.
- **The bug lives in the blob GENERATOR** (`SnapshotService.get_weekly_snapshot` lines 70–211 of `backend/app/services/snapshot_service.py`), which runs when `precompute_and_save` is called (e.g., from `refresh_snapshot_blobs.py` or daily pipeline):
  1. **Re-derives clusters from raw `InsiderTransaction` nodes** via `InsiderClusterService.detect_clusters` (line 73) — never reads SP. So the canonical anchored ledger is irrelevant to what the blob holds.
  2. **Uses `c.window_end` as `signal_date`** (line 88) — `window_end` is the latest tx in the rolling cluster window, so the signal date silently moves forward when new insiders buy weeks later. SP keeps the original anchor. **AVBC is the smoking gun**: blob says May 8, SP says Mar 18 — same underlying cluster.
  3. **`entry_price = _find_close(series, signal_date)`** (line 159) inherits the moving `window_end`, so the dashboard's reported return for the same ticker recalibrates on each blob refresh. SP's `price_day0` is frozen.
  4. **Re-applies filters against today's data** (mcap, earnings-proximity), silently dropping signals that qualified at original signal date but don't today. This is the leading cause of 10-vs-22 count drift.

### Recommendation reached: **remove the blob entirely**

At ~30 signals in the 90d window, the cache is solving a problem we don't have and creating one we do (divergence + staleness). User and Claude aligned on:
- Delete `_load_precomputed`, `precompute_and_save`, ~140 lines of cluster re-derivation in `get_weekly_snapshot`, and `SnapshotBlob` nodes in Neo4j.
- Delete `backend/refresh_snapshot_blobs.py` (and trace its callers in the daily pipeline).
- Replace `get_weekly_snapshot` body with a thin SP reader: query `SignalPerformance` filtered by `signal_date` window + `conviction_tier`, join Company for `name`/`sic`, read SPY's `Company.price_series` for alpha calc, format and return. ~50 lines instead of ~340.
- Tradeoff: each dashboard request runs one Cypher query (<50ms at this volume). No cache, no staleness mode.
- Scope: ~half a day mechanical work; tests around `signal_performance_service` already cover SP-side correctness.

## Architectural finding #1 — Company.price_series refresh path (NOT fixed — proposal stage)

`scanner/form4_scanner.py:_update_company_prices` is the **only writer** of `Company.price_series`. Every downstream price-dependent surface — `SnapshotBlob` (dashboard "Last 30d/60d/90d"), Tracker via `compute_all` historically, signal-detail price charts — depends on the daily scanner running. **Daily Form 4 ingest has been 4 days behind since at least 2026-05-12**, which is exactly why yesterday's dashboard staleness and today's Tracker staleness share the same root cause. Today's surgical refresh papers over the Tracker symptom by hitting yfinance directly per-immature-SP, but the Snapshot/dashboard and signal-detail charts still read the stale series.

### Proposed `refresh_prices.py` (Phase 19, unwritten)

Single idempotent daily-cron-ready job that:
1. Fetches yfinance once per ticker (immature strong_buy cohort + SPY).
2. Writes fresh `Company.price_series` (JSON for now; native-list migration is a separate cleanup).
3. Derives immature SP `price_current`, `return_current`, plus `return_day7/30/60/90` for windows that now have data.
4. Implements "Phase D" — flips signals that have crossed day-90 to `is_mature=true`, freezing the snapshot per v1.2 invariant.
5. Re-emits `DashboardStats` + `SnapshotBlob {30,60,90}` at the end.
6. Hard-asserts: never touches matured rows.

Collapses three current scripts (`backfill_company_prices.py`, `refresh_immature_current_price.py`, `refresh_snapshot_blobs.py`) into one consistent pipeline and closes the `compute_all` retirement gap without resurrecting it.
